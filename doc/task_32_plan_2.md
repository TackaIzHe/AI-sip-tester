# task_32 — перенаправление входящих INVITE на адрес из INVITE (сверх плана, запрос пользователя)

## Запрос

На веб-интерфейсе — галочка, включающая перенаправление INVITE: полученный
станцией вызов (INVITE) перенаправляется на адрес, указанный в этом INVITE.
До задачи INVITE от пира отвечался мимикрией (`405`) или замалчивался
(task_29); автоматической отправки вызова дальше по адресу из запроса не было.

## План (согласован)

Трактовка запроса: «адрес, указанный в INVITE» = `host:port` из Request-URI
(request-line `INVITE sip:<номер>@<host>:<порт> SIP/2.0`); «перенаправление
инвайта» = ретрансляция вызова UAC-ножкой (движок исходящего вызова
`server/station/outbound.ts`, task_30/31), а не 3xx-redirect.

Топология/контракты:

- `server/station/station.ts` — включаемый флаг `forward_invite` (по образцу
  `silent_invite` task_29): методы контракта `Station`
  `forward_invite_mode()` / `set_forward_invite(on)`, поле статуса
  `StationStatus.forward_invite`; флаг — настройка станции, живёт между
  stop/start; `handle_request` не меняется (INVITE забирается хуком раньше
  мимикрии).
- `server/station/outbound.ts` — постоянный хук входящих `on_invite_forward`
  (навешивается в конструкторе движка, активен только при флаге): входящий
  INVITE при флаге «съедается» (пиру не уходит ничего — как в режиме
  молчания) и ретранслируется `dial()`'ом: target — `host:port` из R-URI
  (порт по умолчанию 5060), callee — user из R-URI, caller — user из From,
  origin — src-адрес отправителя (From и второй Via от него, контракт
  task_31). Защита: ответы (`SIP/2.0 …`) и in-dialog re-INVITE живого
  диалога (Call-ID совпадает) — не наши; retransmit исходного INVITE
  (тот же Call-ID) — съедается без повторного набора; занятый движок —
  INVITE съедается без набора; адресат = сама станция — без набора (петля);
  ошибки dial (номер/адресат/сокет) — в журнал вызова, без исключения.
  Флаг+`silent_invite` одновременно: перенаправление приоритетнее (хук
  раньше мимикрии).
- REST (карта 34 → 35): `POST /api/station/forward_invite {"on":bool}` →
  `200` + полный статус (как silent_invite, 409 нет), `400` — `on` не
  boolean. Действует при движке вызова в DI (в бою есть всегда).
- `public/index.html` (вкладка «Станция»): галочка «перенаправлять INVITE на
  адрес из INVITE» под галочкой task_29; состояние — из `GET /api/station`
  (опрос 2 с), переключение — POST; результат ретрансляции виден во вкладке
  «Вызов» (статус/журнал движка).
- Тесты: unit — флаг/стат станции (без движка мимикрия не тронута), цикл на
  loopback: INVITE с R-URI на «пир»-адресат → ретранслированный INVITE у
  адресата (R-URI/From-origin/второй Via), исходному пиру — тишина, дедуп
  retransmit, занятый движок, петля на себя, флаг выкл → 405; api — моки
  Station-контракта во всех четырёх station-файлах + POST `forward_invite`
  200/400.
- Документация: `doc/api.md` (карта 35, endpoint 35, поле статуса в п.20),
  статус в CLAUDE.md, этот файл.

Критерии: `npm run build`, `npm run test:unit`, `npm run test:api` зелёные;
на живой АТС не проверяется (приёмка — за стендом).

## Что сделано

- `server/station/station.ts`: приватный флаг `forward_invite` + методы
  контракта `Station` `forward_invite_mode()` / `set_forward_invite(on)`
  (по образцу `silent_invite` task_29; настройка станции, живёт между
  stop/start), поле `StationStatus.forward_invite`, пункты шапки файла;
  `handle_request` не менялся — INVITE забирается хуком раньше мимикрии.
- `server/station/outbound.ts`: постоянный хук `on_invite_forward` (навешен
  в конструкторе движка, активен только при флаге): INVITE при флаге
  «съедается» (пиру не уходит ничего) и `dial()`ится на `host:port` из
  R-URI: callee — user из R-URI, caller — user из From, origin — src
  отправителя (From и второй Via от него, контракт task_31). Дедуп по
  `last_forward_cid` (retransmit исходного INVITE не поднимает повторный
  набор), занятый движок — съедается без набора, адресат = сама станция —
  без набора (петля), ошибки dial — только в журнал вызова; ответы и
  in-dialog re-INVITE живого диалога хук не трогает.
- `server/controllers/station_controller.ts`: `POST /api/station/forward_invite`
  с телом `{"on":true|false}` → `200` + полный статус, `400` — `on` не
  boolean (409 нет, как у silent_invite). Карта `routes.ts` обновлена.
- `public/index.html` (вкладка «Станция»): галочка «перенаправлять INVITE
  на адрес из INVITE» под галочкой task_29; состояние — из опроса
  `GET /api/station`, переключение — POST с глушением чекбокса на время
  запроса; ход ретрансляции — на вкладке «Вызов» (статус/журнал движка).
- Тесты:
  - `tests/unit/station.test.ts` — +2: флаг/статус станции; без движка
    вызова INVITE по-прежнему получает 405 (флаг — только настройка);
  - `tests/unit/station_outbound.test.ts` — +4 (loopback, T1=20 с чтобы

- `doc/api.md`: endpoint 35 (в тексте раздела «Станция»), карта 34→35,

Для будущих сессий: перенаправление включается галочкой вкладки «Станция»
(флаг станции, переживает stop/start; POST `/api/station/forward_invite`).
«Адрес из INVITE» = host:port из Request-URI; это ретрансляция UAC-ножкой
движка вызова, не 3xx-redirect. Совместно с «не отвечать на вызовы»
приоритетнее перенаправление (хук раньше мимикрии). Без движка вызова в DI
флаг ни на что не влияет. Повторный вызов тем же Call-ID не поднимается;
причина отказа ретранслята — в журнале вкладки «Вызов».

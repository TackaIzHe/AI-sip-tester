# Журнал: падение `npm start` с ConfigError — отсутствовал `.env` (сверх плана, запрос пользователя)

## Выполненный пункт

Запрос: исправить ошибку из лога `log.log` — `npm run start` падал на старте:
`ConfigError: Некорректная конфигурация: SERVER_PORT: целое 1–65535; PBX_HOST: …; …;
SIP_PASS_3: обязателен` (`server/config.ts:132`, стек через `load_config_from_env`
из `server/main.ts:20`).

## План

1. Восстановить отсутствующий образец `.env.example` (значения — из документации
   проекта: doc/task_1_plan_2.md §1.2, doc/plan_2.md, README.md, tests/unit/config.test.ts).
2. Создать `.env` с рабочими значениями стенда (тот же набор).
3. Исключить `.env` из коммитов правкой `.gitignore`.
4. Проверить: build/test зелёные; сервер стартует и отвечает на `/api/health`.

## Симптом → причина → решение

- Симптом: старт сервера падал с `ConfigError`, в списке проблем — ВСЕ поля
  конфигурации разом (HTTP, АТС, мост, все три абонента).
- Причина: в корне проекта нет `.env` — `dotenv.config()` в
  `load_config_from_env()` читать нечего, `process.env` пуст; валидация
  `load_config()` честно репортит каждое отсутствующее поле. При этом
  `.env.example`, на который ссылается README (`cp .env.example .env`),
  никогда не существовал (git-история пуста по обоим путям; `task2/`,
  планировавшийся как источник переноса, на диске отсутствует).
- Решение: создан `.env.example` (образец со всеми 15 переменными, читаемыми
  `server/config.ts`, значения — задокументированный стенд: АТС
  `192.168.80.157:5060`/udp, эта машина `192.168.80.159` (адрес на enp3s0),
  веб :3000, мост :8090, абоненты 9404/123, 52/321, 3203/123, станция
  `192.168.80.159:5060`/both) и `.env` с теми же рабочими значениями;
  `.gitignore` дополнен строкой `.env` (секреты не должны попасть в коммит).
  Код не менялся — валидация работала корректно.

## Что сделано

- `.env.example` (новый): все переменные, которые читает `load_config`
  (`SERVER_PORT`, `PBX_HOST/PBX_PORT`, `SIP_PROTOCOL`, `BRIDGE_HOST/BRIDGE_PORT`,
  `SIP_NUMBER_1..3`/`SIP_PASS_1..3`, необязательные `STATION_HOST/PORT/PROTO`),
  с русскими комментариями-обоснованиями (абонент 3 не регистрируется;
  BRIDGE_HOST — реальный IP, не 127.0.0.1, см. «Грабли» CLAUDE.md).
- `.env` (новый): копия образца с рабочими значениями стенда.
- `.gitignore`: добавлена строка `.env` (`.env.example` остаётся в репозитории).

## Результат проверки критериев

- `npm run build` (`tsc --noEmit`) — зелёный; `npm test` — 259/259 (21 файл),
  зелёные (код не менялся);
- старт сервера с новым `.env` — см. дополнение ниже по итогам приёмки;
- `git status`: `.env` не виден как untracked (игнорируется), `.env.example`
  — новый отслеживаемый файл.

## Отклонения

- Запись/чтение `.env` отклонялись правилами разрешений сессии
  (deny-правило на `.env`-пути) — файл создан оператором по образцу
  `cp .env.example .env`.

## Документация для будущих сессий

- Первичная настройка стенда: `cp .env.example .env` + правка значений
  (README «Запуск»); `.env.example` теперь существует и коммитится, `.env` —
  в `.gitignore`.
- Побочно вскрыто (вне объёма задачи): `/tmp` — tmpfs с `usrquota`, персональная
  квота пользователя превышена файлом `/tmp/xa-W7ILY3` (~13 ГБ) — node/tsc/vitest
  падают на временных файлах с `EDQUOT` («Unknown system error -122»); обход —
  `TMPDIR=~/tmp …` до чистки `/tmp` оператором. Симптом тот же шумит и в профиле
  bash (`pwd: write error: Превышена дисковая квота`).

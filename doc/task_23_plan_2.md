# Задача 23 — стимулы T1–T8 в CLI и веб-интерфейсе (реестр CASES)

Запрос пользователя: «Добавь новые тесты в cli и веб интерфейс», уточнение:
«самые новые тесты … смотри запись номер 22» — т.е. в терминал сервера и
вкладку «Тесты» нужно ввести стимулирующие сценарии T1–T8 генератора утечки
памяти (`doc/los_mem/plan_test.md`, реализация — `doc/task_22_plan_2.md`),
которые были доступны только standalone-CLI `los_mem_main.ts`.

## Что сделано

- `server/los_mem/csv_log.ts` (новый) — CSV-журнал фаз (`ts_utc,ts_ms,
  scenario,kind,text`, план §2.2) вынесен из `los_mem_main.ts` в общий модуль:
  метки обязаны иметь один формат, запускается ли прогон из CLI или из
  сервера; `los_mem_main.ts` переведён на импорт (поведение не менялось).
- `server/los_mem/scenarios.ts` — база дефолтов флагов вынесена из CLI в
  экспорт `BASE_SCENARIO_OPTS` (единый источник слияния «базы → defaults
  сценария → overrides»).
- `e2e_runner.ts` — секция «кейсы-стимулы T1–T8»: фабрика `los_case(id)`
  строит `ScenarioCtx` из `RunContext` (log/phase → шаги прогона, фазы и
  сводка — ещё и событиями `los-start/los-phase/los-summary` в Journal:
  сырой SIP-слой не подключён к `on_trace`, иначе отчёт T-кейса пуст;
  tick → CSV; `stopped` — всегда false, отмены прогона в очереди нет),
  `LOS_QUICK_OPTS` — короткие версии ~1 мин по таблице «быстрого прогона»
  `doc/task_22_plan_2.md` (t1 minutes=1 variant=all, t2 props=100,
  t3 cycles=1 pause=5, t5 observe-min=0, t6 count=1000, …). Кейсы `t1..t8`
  добавлены в `CASES` (имена отчётов `los_t1_dialog_info` … `los_t8_soak`)
  с новым флагом `CaseDef.in_all: false` и хелпером `cases_for_all()`.
- `server/terminal.ts`, `server/controllers/test_runs_controller.ts` — `all`
  раскрывается через `cases_for_all()` (без стимулов); остальной набор
  реестра терминал и вкладка «Тесты» показывают автоматически
  (`implemented_cases()` — единый источник).
- Тесты: `tests/api/test_runs.test.ts` — список GET +t1..t8 и новый тест
  «стимулы в реестре, но вне all».
- Документация: `doc/api.md` §16–17 (новые id, note про `all`), `CLAUDE.md`
  (команды терминала, буллет статуса).

## Ключевые решения (с обоснованием)

- **Короткая версия внутри сервера.** Полные длительности T-сценариев —
  30 мин…сутки; очередь прогонов на процесс одна, интерактивный прогон
  блокировался бы часами. Флаги (variant/props/target/…) в веб не
  прокидывались сознательно — они прерогатива standalone-CLI; здесь только
  дефолты быстрого прогона из таблицы журнала п.22.
- **Стимулы вне `all`.** t1–t8 долгие, а t5 — flood станции; приёмочный
  «запустить все» не должен глушить АТС и длиться больше минуты на кейс.
  Механизм — `CaseDef.in_all: false` + `cases_for_all()` (терминал и
  контроллер), список для показа (`GET /api/test_runs`, `test <без арг.>`)
  остаётся полным.
- **Вердикта стимулу нет** — то же решение оператора, что в п.22: PASS =
  «стимул сгенерирован, сводка получена»; бросок сокета/конфига = FAIL.
  В вердикте — сводка сценария, длительность и путь CSV
  (`reports/los_<t>_<UTC>.csv`, тот же формат для сшивки с мониторингом).

## Результат проверок

- `npm run format:check`, `npm run build` — зелёные.
- `npm run test:unit` 65/65, `npm run test:api` 51/51 (новый тест включён).
- Живой путь веб: `POST /api/test_runs {"case":"t6"}` → 202 → done PASS
  (отчёт-триада `…_los_t6_ipc_frames`, события `los-*` в журнале, CSV и
  hex-дамп в `reports/`); `{"case":"t1"}` → done PASS за 70 с: «NOTIFY
  отправлено 90 (variant=all, 1 мин @ 1.5/с), в диалоги станции 0, ответы
  станции: нет». Станция молчит со времён задачи 22 (см. «Зонд» там) —
  сводка фиксирует это честно, вердикта стимулу нет по определению.
- Живой путь CLI: `test t6` в терминале сервера → PASS, ссылки отчёта,
  `quit` graceful.

## Для будущих сессий

- Новый T-сценарий = запись в `LOS_SCENARIOS` + строка в `CASES`
  (`los_case('<id>')`, `in_all: false`) + короткий дефолт в `LOS_QUICK_OPTS`.
- Захотится прокинуть флаги сweb-вкладки — путь: поле тела
  `POST /api/test_runs` → overrides в `run_case` (пока сознательно нет).
- Станция по-прежнему не отвечает (сброс/защита по источнику или рестарт
  `pa_sip` — см. symptom-заметку `doc/task_22_plan_2.md`); актуальность
  поведения — `npx tsx doc/.probe_losmem_events.ts`.

# Задача 25 — диагностика: почему от станции .157 не доходят сообщения на .159:5060

Диагностическая сессия 2026-11-05 (вне плана). Вопрос оператора: keep-alive от
живой станции `pa_sip 192.168.80.157` не приходит на `192.168.80.159:5060`
(мы — «ведущая станция»; регистрация/вызовы нами сейчас станцией не
принимаются).

## Симптом → причина → решение

- **Симптом:** слушатель на `.159:5060` (эмулятор `SipStation`, TCP+UDP,
  LISTEN подтверждён `ss`) 13+ минут не видит ничего от `.157`; счётчик ядра
  `TcpPassiveOpens` не растёт, `UdpNoPorts` не растёт.
- **Проверки нашей стороны (все чистые):** ping `.157` 3/3 (0.35 мс), ARP
  REACHABLE; симулятор OPTIONS по TCP на `:5060` принят, ответ `200 OK`
  (цепочка приёмника исправна); локального файрвола нет (`nf_conntrack` не
  загружен, `ListenDrops`/`ListenOverflows` = 0, `ip_unprivileged_port_start`
  = 1024 — bind 5060 без root возможен).
- **Вскрытая причина (лог станции, `doc/res_term.md`):** keep-alive шлётся НЕ
  на `:5060`, а на **Contact каждой живой регистрации** транка 06 — на
  эфемерные порты прежних процессов пула: burst 18:53:01 для cdpn 44..47 →
  `192.168.80.159:60501/34159/34512/45665` (осиротевшие регистрации батча
  24..47 прогонов task_18/20/21; процессы мертвы, порты закрыты). Отсюда
  «разные порты у каждой регистрации» в наблюдениях оператора.
- **Второй дефект:** после того burst станция повторных попыток НЕ делает —
  при штатном интервале keep-alive ~21 с (замер task_24, трасса pa_sip) за
  8-минутное окно с автоответчиком `200 OK` на 5060+4 порта из лога не пришло
  НИЧЕГО (`UdpNoPorts` плоский — UDP не слать вообще; TCP — только
  пользовательский `nc -vz` с станции, соединение без данных, путь открыт).
  Т.е. pa_sip после серии отказов на мёртвые Contact-порты опрос пира
  остановил («ведущая не появляется» — chicken-and-egg до оживления
  регистраций).
- **Решение:** оживить регистрации транка живым процессом (`test batch24reg`
  из терминала/веба — станция обновит Contact на живой порт пула и возобновит
  keep-alive туда; UA sip.js отвечает 200 автоматически). Снятие старых
  binding-ов возможно только REGISTER expires=0 с тем же Contact (см.
  task_21) — из нового процесса нереализуемо, устаревают по expires станции.

## Инструменты сессии (зонды, не в бандле)

- `doc/.probe_incoming.ts` — замеры OPTIONS/REGISTER с сокета `:5060` и с
  эфемерного; local-шум как индикатор INPUT-пути.
- `doc/.probe_station_ka_live.ts [сек]` — боевой `SipStation` на
  `STATION_HOST:PORT` (default `.159:5060`, proto both) + печать обращений;
  «станция как клиент» — реверс привычных зондов.
- `doc/.probe_keepalive_capture.ts [сек] [порты...]` — UDP+TCP слушатели+
  автоответчик `200 OK` на порты из лога станции (по умолчанию
  5060,60501,34159,34512,45665).
- Лог станции — `doc/res_term.md` (PBXIPC-SIP TX keep-alive-req, trunkID 06).

## Грабли на будущее

- keep-alive станции привязан к Contact последней регистрации абонента, а не
  к порту 5060; «слушаю 5060 и жду станцию» — неверная модель для транка с
  per-номерными регистрациями.
- Без root (tcpdump/CAP_NET_RAW недоступен) входящие TCP на ЗАКРЫТЫЕ порты
  невидимы счётчиками (RST не двигает `TcpPassiveOpens`); UDP на закрытые
  порты виден по `UdpNoPorts`. Для полного захвата нужен `sudo tcpdump`.

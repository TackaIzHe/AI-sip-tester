архитектура проекта:
    1. модуль sip протокола
    2. модуль сервера на node ts
    3. модуль rest api
    4. модуль cli
    5. модуль логера
    6. модуль журнала

ход вызова:
    req -> api -> node ts -> sip -> ip ats
    req -> cli -> node ts -> sip -> ip ats

описание модулей:
    1. модуль sip нужен для работы с протоколом сип (обработка всех методов sip: invite, ack, bye, и тд.)
    2. модуль сервера нужен для превращения api запроса в запрос sip протокола
    3. модуль rest api нужен для общения с пользователем
    4. модуль cli долже выступать как альтернатива api (если нужно протестировать функционал через терминал сервера)
    5. модуль логера нужен для включения только нужных администратору логов

API: 
    1. должен быть реализован на потерне rails
    2. Роуты:
        1. /sip/<метод сип протокола(register, ack, bye)> в аргументах передаётся номер телефона и пароль если нужен
        2. /journal_html/<номер журанала>  (журналы создаются при выполнении тестов)
        3. /journal_md/<номер журанала>  (журналы создаются при выполнении тестов)
        4. /doc (endpoint на котором можно посмотреть докуметацию проекта через swager)
        и тд.

SIP:
    1. должен быть реализован как модуль на пододии express(каждый методы сип протокола должны вызываться одной функцией (sip.ACK(<номер телефона>) и тд.))
    2. настройка должна происходить от родительского инстанса (пример const sip = new SipProto(); sip.dest = "192.168.0.142" и тд.)

    сип должен быть реализован по стандарту rfc 3261, для этого приложения не нужен мост так как нет FRONT-END модуля

журналы:
    Созадются при выполнении тестов, описываю что произошло в процесе выполнения теста
    журналы оздаются в двух форматах в формате html и md

Тесты:
    для каждой функции должен быть тест
    тесты должы запускаться через cli
    у каждого теста есть номер и краткое описания для запуска через терминал
    все тесты можно запустить одной командой all в cli

Тесты Sip:
    все выше перечисленные пункты из "Тесты" сюда входят
    должны быть тесты попытки вызова(абонент может быть не зарегистрирован)

Использование модулья SIP:
    должно быть очень простым (указал конечную точку(АТС) вызвал метод(указываешь номер и пароль абонента если это регистрация) и получил результат, вся сложная логика должна обробатыватся самим модулем)

код стайл
    у каждой функции должен быть коментации над ней с катким описанием что она делает
    использовать Snake_case для названий функций, класов, файлов
    в файле документации должна быть подробная схема вызова
    в файле документации должна быть подробное описание работы функции

Структура директорий:
    |src/
    |---|static/           /* файлы которые сервер на node ts раздаёт через mideleware */
    |---|API/              /* файлы отнасящиеся к api (роуты, endpoints, midleware)*/  
    |---|---|swager/       /* файлы связанные с модулем swager для доступа к документации api через api*/
    |---|SIP/              /* файлы которые отвечают за обработку сип протокола */
    |---|logger/           /* файлы логера */
    |---|midleware/        /* файлы миделвейров которые используются во всём проэкте (в нескольких модулях)*/
    |---|cli/              /* упровление командной оболочкой (запуск тестов, просмотр логов, включение логов, пользовательский ввод)*/
    |---|index.ts          /* точка входа програмы инициализируется api и остальные модули*/
    |.env                  /* переменые среды окружения */
    |package.json          /* зависисмости проекта */
    |tsconfig.json         /* конфига ts */
    |doc.md

    также в каждой папке должен быть файл CLAUDE.md в котором будет описанно что за модуль и для чего он, также должен быть файл doc.md в котором подробная докумнетация на весь модуль с полныб разьяснением каждой функции

    в файле ./doc.md должно быть описанно о каждом модуле для чего он и что в нём можно найти

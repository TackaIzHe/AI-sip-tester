# Журнал: обработка EADDRINUSE при старте сервера (сверх плана, запрос пользователя)

## Выполненный пункт

Запрос: исправить ошибку из лога `error.md` — `npm run start` падал с
`Error: listen EADDRINUSE: address already in use :::3000` (необработанный
`'error'`-событие HTTP-сервера: `node:events:497 throw er`).

## Симптом → причина → решение

- Симптом: второй запуск сервера при уже работающем первом завершался
  аварийно — трейс node:events вместо внятного сообщения; терминал после
  падения оставался в raw-режиме readline.
- Причина: у объекта, возвращённого `app.listen()` в `server/main.ts`, не было
  обработчика `'error'` — узел для события `'error'` без слушателя бросает
  ошибку; порт 3000 занимал прежний экземпляр `tsx server/main.ts`.
- Решение: в `server/main.ts` после `start_terminal` — обработчик
  `server.on('error', …)`: для `EADDRINUSE` сообщение по-русски («порт занят —
  завершите прежний запуск или смените SERVER_PORT в .env»), для прочих кодов
  — текст ошибки; затем `repl.close()` (вернуть терминал из raw-режима) и
  `process.exit(1)`.

## Что сделано

- `server/main.ts` (единственное изменение): обработчик `'error'` транспорта
  слушателя с комментарием-обоснованием (почему навешан после
  `start_terminal` — событие асинхронно, `repl` уже создан; почему без
  `shutdown()` — регистраций на этом этапе ещё нет, а код выхода 1 нужен
  скриптам).

## Результат проверки критериев

- воспроизведение на живом стенде при занятом :3000 — `npm run start`: вместо
  трейса `[sip-atc] порт 3000 уже занят — завершите прежний запуск сервера
  или смените SERVER_PORT в .env`, код выхода 1;
- `npm run build` — зелёный; `npx prettier --check server/main.ts` — зелёный,
  строки ≤ 90 символов;
- `npm run test:unit` (49) и `npm run test:api` (50) — зелёные (код не затрагивался).

## Отклонения

- Нет.

## Документация для будущих сессий

- Конфликт порта теперь штатный сценарий: перед новым запуском достаточно
  завершить прежний процесс (`quit` в REPL сервера, SIGINT/SIGTERM) — либо
  сменить `SERVER_PORT` в `.env`.
- Обработчик ловит и прочие ошибки слушателя (например EACCES на привилегированном
  порту) — тот же путь: сообщение + выход с 1.

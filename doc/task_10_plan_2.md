## Отклонения с обоснованием

1. **`doc/api.md` — один файл, а не `doc/api/<category>.md`.** План допускает
   оба варианта; 16 endpoints читаются с карты-таблицы быстрее, чем по шести
   файлам, а link-и контроллеров (`routes.ts` уже ссылается на `doc/api.md`).
2. **Живые curl-ответы не перечётывались** (сервер не поднимали): тела
   ответов сверены с реализацией контроллеров и ассертами `tests/api/` п.9,
   которые фиксируют ровно эти коды и формы — источник не «менее честный».
3. **DELETE `/api/subscribers/:number/register` задокументирован как 200 и для
   неизвестного номера** — фактическое поведение `SipSubscriberPool.unregister`
   (no-op без записи), план кода для него не задавал; изменять код п.10 не
   должен.

## Симптом → причина → решение (наблюдения)

- При сверке тела ответа `POST /api/subscribers/.../register` возник вопрос
  «почему `code: 0, text: ""` при успехе?» — это не SIP-код, а заглушки
  `RegisterOutcome` (пул кладёт реальные код/текст только в исключение при
  отказе). Зафиксировано в api.md примером, чтобы читатели не ждали `code: 200`.
- Формат id прогона для `noanswer` — `run_<UTC>_casenoanswer` (в
  `test_runs_controller` id строится как `case${id}` без разделителя) — в
  api.md приведён точный формат генерации, а не «красивый» шаблон.

## Дефект, вскрытый проверкой «журналы отдаются на index.html во вкладку Отчёты»

- **Симптом** → **причина** → **решение**:
  - Вкладка «Отчёты» в реальном браузере показывала «не удалось загрузить
    отчёты» и пустой список (при любом ненулевом числе отчётов).
    Причина: в `public/index.html` `render_report_item` присваивал `meta.textContent`
    строку с HTML-разметкой ссылки `<a …>` (textContent разметку не парсит),
    следующая строка `meta.querySelector('a').addEventListener(...)` получала
    `null` → TypeError → исключение ловил `try/catch` функции `load_reports`
    и рендер списка обрывался. Дефект родился в п.6 и был пропущен, потому что
    критерий п.6 проверялся curl-эквивалентами без исполнения JS (см. допись в
    `doc/task_6_plan_2.md`).
    Решение: ссылка «новая вкладка» строится DOM-API (`createElement('a')`,
    href/target/rel, `stopPropagation` сохранён).
- **Проверка исправления** — два новых зонда (паттерн `doc/.probe_*`):
  - `doc/.probe_reports_page.ts` (серверный уровень, `npx tsx`, без сети):
    GET / (вкладка на месте), GET /api/reports (18 записей, html-пути),
    каждый `/reports/<id>.html` → 200 с шапкой/вердиктом/этапами, каждый
    `GET /api/reports/:id` → meta.verdict + events. ✅
  - `doc/.probe_reports_browser.ts` (браузерный уровень): боевой `create_app`
    на эфемерном порту + **jsdom** (временный `npm i -D --no-save jsdom@24` —
    на Node 18 jsdom 30 несовместим; в package.json/лок не сохранялся, после
    проверки удалён): клик по вкладке «Отчёты» → список из 18 записей с
    ссылками, клик по отчёту → iframe `/reports/<id>.html` → 200 с журналом,
    «обновить» — перезагрузка. ✅ (с прежним кодом этот шаг падал — зонд
    воспроизводит дефект).
- `npm run build` и `npm test` (90/90) после правок — зелёные.
